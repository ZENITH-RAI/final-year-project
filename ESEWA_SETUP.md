# eSewa payment setup

The marketplace uses **eSewa ePay V2**.

## UAT / project demo

The code defaults to eSewa's public UAT merchant values:

- Product code: `EPAYTEST`
- Payment URL: `https://rc-epay.esewa.com.np/api/epay/main/v2/form`
- Status URL: `https://uat.esewa.com.np/api/epay/transaction/status/`

Test wallet credentials currently documented by eSewa:

- eSewa ID: `9806800001` (the docs also list 2/3/4/5 variants)
- Password: `Nepal@123`
- Verification token: `123456`

Set `ESEWA_ENVIRONMENT=uat`. The public UAT product code and secret have safe test defaults in `services/esewa_service.py`, or can be overridden with environment variables.

For a deployed app, also set `PUBLIC_BASE_URL` to its public HTTPS base URL (for example, `https://your-app.vercel.app`). This ensures eSewa redirects back to the real public site rather than an internal proxy address.

## Production

Set all of these on the server/deployment platform:

```text
ESEWA_ENVIRONMENT=production
ESEWA_PRODUCT_CODE=<your merchant product code>
ESEWA_SECRET_KEY=<your private merchant secret>
```

Never commit a production merchant secret.

The customer must always sign in on the hosted eSewa page. This application only creates the signed payment request, receives eSewa's signed response, and confirms it using eSewa's transaction-status API; it never collects an eSewa ID, password, PIN, or verification token.

## Payment flow in this project

1. Buyer opens an active marketplace listing.
2. `POST /listing/<listing_id>/buy` creates an Order + Payment and reserves the listing.
3. The backend creates the eSewa HMAC-SHA256 signature.
4. The browser POSTs the signed form to eSewa.
5. On success, the app validates eSewa's signed callback.
6. The backend also calls eSewa's transaction status API.
7. Only a verified `COMPLETE` status changes the order to `PAID` and listing to `SOLD`.
8. Failed/cancelled payments release the listing; pending/ambiguous payments remain pending.

When eSewa redirects back before its status API is updated, the app shows a pending state rather than treating a paid transaction as failed. The buyer can then use **Check payment status** to complete processing safely.

## Database migration

After pulling these changes, run:

```bash
flask db upgrade
```

This applies `d4e5f6a7b8c9_add_marketplace_and_payments.py` and creates `listings`, `listing_images`, `orders`, and `payments`.

## Local callback note

eSewa redirects the browser to the `success_url` / `failure_url` generated by Flask. For a local demonstration, run the Flask app on the same machine/browser. If the payment provider refuses or cannot reach your local callback URL in your setup, expose the app over HTTPS with a development tunnel and use that public URL.
